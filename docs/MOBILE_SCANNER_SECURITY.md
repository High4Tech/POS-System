# Tech Store Scanner 1.1 security review

Reviewed the Android source, merged manifest, Gradle runtime dependency graph, and local receiver code. The baseline was the upstream Kotlin checkout at `cab2711c33e7ee6c5e74cca38352858db8289469`, the public unsigned v0.1.0 APK, and the previous Tech Store test APK. The original APK was inspected statically and was never installed or executed.

The public artifact's SHA-256 is `FAAD1CA77D5770B24D6DA4396FCE07B82FE73924A542B8155D7BFE30C908CFA8`. Its package name, minimum and target SDK, permission set, cleartext/backup flags, ML Kit components, and native library inventory were consistent with the corresponding upstream source and dependency declarations. This was not a reproducible-build or byte-for-byte comparison. [Published scanner release](https://github.com/KKacobls/scanner-app/releases/tag/v0.1.0)

## Verification boundary

Static checks cover the inspected source, merged manifest, dependency list, and APK contents. A November 17, 2026 OSV check returned zero advisories for ten queried coordinates covering ZXing Core, OkHttp, Okio JVM, Core KTX, AppCompat, Material Components, and four CameraX modules. This check covers those versions and the advisories in the database. [OSV](https://osv.dev/)

POS Scannar 1.4 replaces the ZXing Core camera decoder with the bundled ZXing-C++ 2.3.0 Android wrapper. Barcode recognition remains local. [ZXing-C++ Android wrapper](https://github.com/zxing-cpp/zxing-cpp/tree/v2.3.0/wrappers/android)

The Windows tests use loopback TLS to verify pairing, authentication, event deduplication, pause behavior, protocol compatibility, and common routing for the three connection labels. Android JVM tests exercise pairing input validation, transport route selection, and representative barcode decoding. These checks do not substitute for a physical phone, real Bluetooth PAN, USB RNDIS/NCM, or camera testing. Windows and Android tethering support varies with hardware, driver, and carrier configuration.
