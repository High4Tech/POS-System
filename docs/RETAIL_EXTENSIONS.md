# Local retail and invoice extensions

This upgrades the existing modified app. No replacement checkout, catalog, cloud store or Android rebuild was created. All tests used isolated databases; no sample transactions/providers/customers were inserted into the real store.

## Completed behavior

- Business onboarding and Settings → Business Features provide Grocery/Kiryana, Supermarket/Minimart, General Retail, Pharmacy, Electronics, Mobile/Recharge and Other. Defaults follow the supplied matrix; four independent toggles control loose goods, packaging, wallet records and recharge. Disabling a module retains history. Digital history remains reachable after disabling its entry actions.
- Settings tab headers retain their positions and use blue/white selection. The brand gradient stays blue. Info controls close on pointer leave, repeated click or focus loss. Shared store identity is synchronized in both settings flows; a leftover Demo Account/Tech Store placeholder is replaced by the entered legal name. An intentional trading name remains distinct from the legal name. Udhar/Pay later checkout has editable/searchable existing-customer selection.
- Measured products use kg/litre prices and integer gram/ml stock. Piece stock is an integer count. Expiry batches use the same integer base units. Loose barcodes are optional, with a unique internal identifier. The register has search, weight/volume, 1 / ½ / ¼ selectors and amount-based sale entry. Amount entry floors to measurable base units and shows actual quantity/charge before confirmation. A conflicting existing manual cart-price override requires adjusting/removing that line first. Stock changes only on successful checkout; the original batch/expiry checks remain active.
- Products can define one purchase package, pieces per package, distinct package barcode, package cost and optional full-package price. Purchases convert packages into base pieces once. Whole-package sales retain their sold unit and configured price while deducting only the corresponding pieces. Individual and package barcodes resolve separately, including equivalent GTIN forms.
- Digital Services records cash-in/out, load and locally configured mobile packages. Providers have allowed types, opening recorded float, policies and active status. No current tariffs are seeded. Draft/pending/failed entries post no balances. Confirmation requires a provider reference and explicit acknowledgement of the external result. Confirmation IDs and posting uniqueness prevent duplicate postings; already completed provider references are rejected. Reversals are separate linked transactions with compensating postings. Reports net reversals, split physical/loose retail revenue from service income, and never treat wallet principal as retail sales revenue. Float is an internal recorded balance, not a live provider balance.
- Completed invoices expose exactly three primary actions in order: Print Receipt, WhatsApp, Download. Sales-history details offer the same three actions and reopen the saved invoice action view. Actions never rerun checkout or change stock/numbering. New Sale/Close is secondary. Printing uses the configured Windows queue on a background STA thread, with queue-status checks, retry/settings and 58/80 mm/A4 sizing. Active printing prevents an update install. A submitted job is not reported as verified paper output.
- WhatsApp normalizes saved Pakistani phone formats and preserves international country codes. A registered desktop protocol handler is tried first; missing/failed launch falls back to Web, with an explicit browser fallback afterward. The cashier reviews and sends. Missing numbers open a correction form; saving contact changes is opt-in and uses the existing customer-account guard. Messages are localized/editable and use saved invoice values. PDFs remain local for manual attachment; no file upload or message sending occurs automatically.
- Download uses a Save File dialog and `Invoice-{number}.pdf`, with the configured export folder or Documents as the default. The managed cache stays under the selected data folder's PDFs directory. A revision/content hash permits verified reuse and repairs corrupted cached files.

- `20261119180000_RetailMeasurements`: exact decimal-text backfill into integer product and expiry-batch balances, package/minimum-stock metadata, sale/purchase unit snapshots and barcode collision checks. Deprecated TEXT quantity columns remain for migration traceability; they are no longer live stock balances. The migration rejects quantities that cannot be represented at the required precision rather than silently losing stock.

Commercial schema generation is now 2; releases must declare compatible schema bounds. Backup/restore compatibility includes both migrations. Restore an application/database pair together; never run the old binary against the migrated database.

## Limits and references

No physical printer paper output, actual WhatsApp recipient chat/delivery, disconnected printer hardware, phone camera/Wi-Fi/Bluetooth or new Android binary was tested in this extension. Those require a user/device check. Windows drivers may report printer availability late; verify paper output after submission. Wallet/recharge actions are manual records only, with no provider API or credentials. No production FBR, live Cloudflare deployment or trusted signed-installer pilot is claimed here; existing commercial release gates remain in COMMERCIAL_OPERATIONS.md.
